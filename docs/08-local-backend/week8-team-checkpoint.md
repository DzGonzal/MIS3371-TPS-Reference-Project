# Week 8 — Team Repository Checkpoint (4 Points)

Extend your **existing** project repository with a local backend and a small test file. Do not create a disconnected project, copy the Expense Reimbursement scenario, or connect your frontend to the backend yet.

## Deliverables

1. Create `backend/` with a project-specific processing function and a local test file.
2. Identify and implement 2–3 critical rules from your own prior requirements/workflow/data design. Include at least one invalid-case rule and one meaningful routing/business decision.
3. Test **at least six named cases**: at least two valid, two invalid, and two boundary/edge cases (adapt where a numeric threshold is not applicable).
4. In repository documentation, record each case's input, expected result, actual result, and whether it passed.
5. Push work to your existing team GitHub repository and update the team leader contribution tracker.

No API endpoint, `fetch()`, Express, AWS, database, or frontend integration is required for Week 8. Milestone 2 remains a separate **60-point client-side assessment**.

## Four-point rubric

| Criterion | Points |
|---|---:|
| Backend structure / runnable local logic | 0.50 |
| Project-specific transaction data | 0.25 |
| Independently enforced critical rules | 1.00 |
| Valid, invalid, and boundary/edge tests | 1.00 |
| Understandable structured results | 0.50 |
| Documented expected/actual testing evidence | 0.25 |
| Repository organization / contribution evidence | 0.50 |
| **Total** | **4.00** |

The instructor reference demonstrates *equivalent ideas*, not mandatory expense-specific field names or thresholds. Actual repository evidence matters; commit count alone is not a grade.
